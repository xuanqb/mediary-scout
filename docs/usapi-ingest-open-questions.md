## 二、需要 USAPI 确认或修改的 3 件事

### 1. 字幕交付顺序（硬冲突）

v0.4 把这些位置写成了硬性要求：

- 4.5 节：关联文件先移、视频最后移

- 11.3 节：要求巡影确认

但双方此前已确认：**字幕文件不影响入库，巡影不需要为字幕调整交付顺序**。巡影当前也不保证该顺序。

请 USAPI 选择：

- [ ] **A. 删除硬性要求**：删掉 4.5、10.4、11.3 中的顺序要求，以及验收 12.13 / 12.14；字幕晚到可忽略。
- [ ] **B. USAPI 自行处理**：保留现有序要求，由 USAPI 增加稳定窗口或补移逻辑。
- [ ] **C. 巡影改代码**：巡影改造 `moveToSeason` / `flattenMovie` 的移动顺序，需要额外开发。

如果选 A，请一并确认晚到字幕的处理：

- [ ] USAPI 忽略并清理
- [ ] 巡影在追踪结束时清理
- [ ] 保留不管

### 2. `following` 与 `completed` 的边界

v0.4 的 2.4 / 5.3 写的是：

- `following` 任务低频轮询，不阻塞串行队列；
- 当前快照完整但仍有后续 → 继续 `following`；
- 季完结且齐全 → `completed`；
- `completed` 后不再投递新集。

巡影理解并按此实现：

- 内部季状态为“已完结且全部已获取” → API `completed`
- 季未完结 / 仍有缺集 → `following`
- 电影交付完成 → `completed`

需要 USAPI 确认：

- [ ] 同意 `following` 后续可以转为 `completed`
- [ ] 同意 `completed` 后巡影冻结该目录，不再投递任何新集
- [ ] 如果 TMDB 后期又给已 `completed` 的季加集，巡影应停止投递（不重新变回 `following`）

---

### 3. `no_resource` 后巡影是否继续追踪

v0.4 只说“当前时点没有可用资源 → `no_resource`”，没有说明巡影是否继续追。如果巡影继续追、USAPI 又走 MoviePilot 订阅，会重复。

巡影建议按以下规则：

| 场景 | 巡影状态 | 是否继续追踪 | USAPI 动作 |
|---|---|---|---|
| 电影无资源 | `no_resource` + `NO_RESOURCE` | 否 | 可订阅 |
| 已完结季无资源 | `no_resource` + `NO_RESOURCE` | 否 | 可订阅 |
| 连载中季暂无资源 | `following` | 是 | 不订阅，等 115 事件 |
| 未上映 / 尚无已播集 | `no_resource` + `UNRELEASED` | 否 | 走 MoviePilot 订阅 |
