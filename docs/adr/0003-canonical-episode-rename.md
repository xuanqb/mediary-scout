# 0003 — 非电影视频按 Emby 可解析格式改名

- 状态：已采纳
- 日期：2026-11-08

## 背景

2026-06-13 / 2026-06-15 起，acquisition-v2 刻意保留视频原始文件名：电影靠 `Title (Year)` 包裹目录识别，剧集靠季目录 + agent 判断识别。但落到网盘后，Emby 实际读取的是 SmartStrm 从源文件名生成的 `.strm`；源文件名不含集号时（例如 `199.4K.mp4`），生成的 `199.4K.strm` 不会被 Emby 识别为 S01E199。

只有 app 知道 agent 已确认的集号映射；SmartStrm、Emby、MoviePilot 都无法从 `199.4K` 推出集号。MoviePilot 的 `TV_RENAME_FORMAT` 已经是本库的命名约定，但这轮运行证明它不会处理一个无法识别的文件。

## 决策

对本次 `Landed` 的电视剧 / 综艺 / 动漫视频，若文件名没有携带与 agent 映射一致的 `Episode Key`，在移入季目录前把源文件改名为按 MoviePilot `TV_RENAME_FORMAT` 渲染出的 `Library Filename`：

- 电影不改名；已能解析的文件保持原名；
- 连续多集文件命名为 `SxxEyy-Ezz`；非连续或无法判断时保留原名并记警告；
- 标题中的非法字符替换为全角或空格；
- `videoFormat` / `releaseGroup` best-effort 填充，缺失时按模板条件省略；`part` 暂不填；
- 名称冲突追加 ` - v2` / ` - v3`，绝不覆盖既有文件；
- 随行外挂字幕对齐最终视频名；
- 改名失败仍按原名移动并标记 `Obtained`，同时写审计警告；
- app 不接管 SmartStrm 产物，也不回填历史文件。

模板以 MoviePilot 的 TV 模板为准，由 app 内一个类型安全的格式化函数渲染，不引入 Jinja2 引擎。

## 后果

- 反转了“视频永不重命名”的旧规则，但只作用于新落盘且不可解析的非电影视频。
- Emby 可见性从“依赖资源命名”变成“由 app 保证”；代价是 app 需要维护一条与 MoviePilot 模板一致的命名规则。
- 现有 `199.4K.mp4` 不回填；如果 SmartStrm 未来再次为它生成 `199.4K.strm`，仍可能出现重复或无法识别的条目。
- 改名是对源文件的写操作；失败时仍会留下一个 Emby 不可见的已入库文件，只能靠审计事件发现。

## 考虑过的替代方案

- 只把源文件改成最小可解析名 `Title - SxxEyy`，让 MoviePilot 补全：这轮 MoviePilot 并未处理 `199.4K`，不可靠。
- 配置 Emby 解析规则：文件名本身没有集号，无法可靠推断。
- 所有新视频一律改名：会重命名本来已可解析的文件，扩大冲突面。
