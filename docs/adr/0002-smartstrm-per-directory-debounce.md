# 0002 — SmartStrm 按目录去抖，而不是每次落盘都触发

- 状态：Superseded — SmartStrm 集成已移除
- 日期：2026-11-04

## 背景

一次获取可能在同一轮里把多集、甚至跨季的文件写进同一部剧的目录。SmartStrm 的 `a_task` 每次都会扫描 `storage_path`；如果每落一集就触发一次，一轮下来会连续扫描十几次，既慢又容易互相干扰。

但只做「固定延迟」也有问题：持续有文件落盘时，延迟会被不断推后，用户可能很久都等不到扫描。

## 决策

以最终目录（`storage_path`）为键做合并：

- 同一目录在静默期（默认 15 秒）内反复出现落盘事件，只保留一个待发送任务，并把发送时间推到「最后一次事件 + 静默期」；
- 同时设置硬上限（默认 120 秒）：从第一次事件算起最多等这么久，到期一定发送；
- 两个参数都可在设置里调整；
- 待发送队列持久化在账号设置里，进程重启后仍会补发；投递结果单独记录，失败按指数退避重试。

## 后果

- 一次批量落盘只触发一次扫描；持续落盘也不会无限期延后。
- 去抖是「按目录」而不是「按标题」：同一部剧落在两块盘上时，每个盘各自触发，因为它们的挂载前缀不同。
- 投递队列和日志是轻量的 JSON 设置项，不新增数据库表；单进程部署下由互斥锁串行写入。
