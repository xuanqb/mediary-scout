# 发布说明

每个发布标签 `vYYYY.MM.DD`（同一天第二次发布起 `vYYYY.MM.DD.2`、`.3`…）对应这里一个同名 `.md` 文件。

格式：每条一行，以「新增」「改进」「修复」开头，后面一句用户能看懂的话。不写 PR 号、函数名、内部术语。

    - 修复 巡检不会在一次运行里把同一个资源包转存两次
    - 新增 SmartStrm 自动化：落盘后按目录触发 a_task，同一目录合并为一次扫描
    - 改进 转存中途失败留下的临时文件夹，系统会自己收拾干净

只有在作者自己的实例上验证过的 main 提交才打标签。流程：写好本文件 → 合并到 main → 在该提交上 `git tag vYYYY.MM.DD && git push origin vYYYY.MM.DD`。用轻量标签，不要加 `-a` 或 `-m`。

推标签之后，用本文件正文（去掉标题）在 GitHub 发布「巡影 vYYYY.MM.DD」。部署方升级时在部署目录运行 `./scripts/deploy.sh`。
